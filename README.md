# metallomaster.by

Сайт производителя металлоизделий из листовой стали (Минск): дымоходы, колпаки на трубу,
воздуховоды, доборные элементы кровли.

Статический сайт на Astro 7. Сборка — обычная папка с файлами, никакого сервера приложений.

## Что нужно

- **Node 22.12**
- **npm**

## Запуск

```bash
nvm use 22
npm ci
npm run dev
```

## Команды

| Команда           | Что делает                                           |
| ----------------- | ---------------------------------------------------- |
| `npm run dev`     | dev-сервер с горячей перезагрузкой                   |
| `npm run stop`    | остановить фоновый dev-сервер                        |
| `npm run build`   | сборка в `dist/`                                     |
| `npm run preview` | отдать собранный `dist/` — так сайт выглядит в проде |
| `npm run check`   | проверка типов и `.astro`-шаблонов                   |
| `npm run lint`    | ESLint с автопочинкой                                |
| `npm run format`  | Prettier по всему проекту                            |

Перед завершением любой задачи прогоняйте три команды, все должны быть зелёными:

```bash
npm run build && npm run check && npm run lint
```

## Как обновить сайт

Хостинг — **domain.by**, панель ispmanager. Корень сайта:

```
/var/www/metallomaster/data/www/metallomaster.by
```

**1. Собрать.** Убедитесь, что `.env` на месте, иначе выложите сайт с нерабочей формой:

```bash
npm run build
```

**2. Упаковать содержимое `dist`** (точка после `-r` обязательна — она и убирает обёртку
`dist/`, и забирает скрытый `.htaccess`):

```bash
cd dist
zip -r ../metallomaster.zip . -x '.DS_Store' '*/.DS_Store'
```

**3. Залить.** ispmanager → `File manager` → перейти в корень сайта → `Upload` → выбрать
архив. В файловом менеджере должен быть включён показ скрытых файлов.

**4. Распаковать.** Отметить архив галочкой → `Archive` → `Extract`, в текущую папку, без
создания подпапки. Затем удалить сам архив.

**5. Проверить.** Обязательно убедиться, что в корне лежит `.htaccess` — без него не
работают ни редиректы, ни https, ни заголовки безопасности, и сервер об этом молчит.

```bash
curl -I https://metallomaster.by | grep -i server      # должен быть Apache
curl -I http://metallomaster.by/                       # 301 на https
curl -I https://metallomaster.by/kolpak-na-stolb.html  # 301 на новый адрес
curl -I https://metallomaster.by/no-such-page/         # 404, не 200
```

При чистке корня перед заливкой **не удаляйте** `.well-known` (по нему продлевается SSL)
и `cgi-bin`.

## Автоматический деплой

Ветки и что с ними происходит:

| Ветка  | Что запускается  | Куда попадает                                  |
| ------ | ---------------- | ---------------------------------------------- |
| `dev`  | `preview.yml`    | превью на GitHub Pages, закрытое от индексации |
| `main` | `production.yml` | боевой сайт на domain.by через SSH + `rsync`   |

Боевой деплой собирает, прогоняет `check` и `lint`, выгружает только изменившиеся файлы
и проверяет живой сайт: главная открывается, старый адрес отдаёт 301, несуществующий — 404.
`.well-known` и `cgi-bin` из синхронизации исключены — иначе `rsync --delete` снёс бы их
вместе с автопродлением SSL.

Пока не задана переменная `DEPLOY_ENABLED=true`, боевой прогон пропускается.

### Разовая настройка

1. Запросить SSH у `support@domain.by` — письмом с контактного адреса хостингового
   аккаунта. На всех тарифах доступен, но только по запросу.
2. Создать ключ и положить публичную часть на хостинг в `~/.ssh/authorized_keys`:

   ```bash
   ssh-keygen -t ed25519 -f ~/.ssh/metallomaster_deploy -C "github-actions" -N ""
   ```

3. Добавить секреты в Settings → Secrets and variables → Actions → Secrets:
   `SSH_PRIVATE_KEY` (содержимое файла без `.pub`), `SSH_HOST`, `SSH_PORT`, `SSH_USER`,
   `WEB3FORMS_KEY`.
4. Там же на вкладке Variables добавить `DEPLOY_ENABLED` = `true`.
5. Для превью: Settings → Pages → Source → GitHub Actions.

Если нужен ручной контроль над выкатом — Settings → Environments → `production` →
Required reviewers. Тогда Actions соберёт сайт и остановится, ожидая подтверждения.

### Что важно помнить про сервер

Всё поведение сервера лежит в `public/.htaccess`, он копируется в корень сборки: карта
301-редиректов со старых адресов, http → https, www → без www, завершающий слеш,
кэш-заголовки, сжатие, своя 404-я и заголовки безопасности.

- Файл читают только Apache и LiteSpeed — nginx игнорирует его молча.
- Переименовали или удалили страницу — добавьте старый адрес в этот файл. Других копий
  карты 301 нет.
- Кэш для `/_astro/` задаётся не здесь, а на стороне nginx: статику он отдаёт сам, мимо
  Apache. Настраивается через поддержку хостинга.
- HSTS стоит на `max-age=300`, чтобы ошибку с сертификатом можно было откатить за пять
  минут. Через неделю спокойной работы меняется на два года.
- CSP пока в режиме отчётов (`Content-Security-Policy-Report-Only`). Когда консоль чиста,
  суффикс `-Report-Only` убирается.
