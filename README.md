# metallomaster.by

Сайт производителя металлоизделий из листовой стали (Минск): дымоходы, колпаки на трубу,
воздуховоды, доборные элементы кровли.

## Запуск

Нужен **Node 22.12+** (Astro 7 не запустится на более старом) и npm.

```bash
nvm use 22          # если пользуетесь nvm
npm ci
npm run dev         # http://localhost:4321
```

| Команда           | Что делает                                                |
| ----------------- | --------------------------------------------------------- |
| `npm run dev`     | dev-сервер с горячей перезагрузкой                        |
| `npm run stop`    | остановить фоновый dev-сервер                             |
| `npm run build`   | сборка в `dist/` (34 страницы + обработанные изображения) |
| `npm run preview` | отдать собранный `dist/` — так сайт выглядит в проде      |
| `npm run check`   | проверка типов и `.astro`-шаблонов (`astro check`)        |
| `npm run lint`    | ESLint с автопочинкой (правила архитектуры — тоже здесь)  |
| `npm run format`  | Prettier по всему проекту                                 |

**Перед завершением любой задачи** прогоняйте три команды — все должны быть зелёными:

```bash
npm run build && npm run check && npm run lint
```

## Правила, которые ломать нельзя

Четыре договорённости, на которых держится проект. Первые две проверяет ESLint —
нарушение валит `npm run lint`.

**1. Импорты только вниз по иерархии.**
`atoms ← molecules ← organisms ← templates ← pages`. Атом не знает о молекулах, молекула —
об организмах. `lib/` и `config/` доступны всем уровням.

**2. Переносимость: логика отдельно от фреймворка.**
Файлы в `lib/*.ts` не импортируют ничего из `astro`/`astro:*` — при переезде на другой
фреймворк они переносятся как есть. `.astro`-файлы — тонкие шаблоны: разметка, классы,
вызовы функций из `lib/`. Интерактив — функции `init*(root: HTMLElement)`, подключаются
через `<script>` в компоненте.

Исключения-адаптеры, где фреймворк-импорты разрешены (список закодирован в `eslint.config.js`):
`pages/`, `components/templates/`, `lib/content.ts`, `lib/types.ts` (только тип `ImageMetadata`),
`config/site.ts`, `components/atoms/picture.astro`.

**3. Стиль — только через токены.**
Все цвета, размеры и отступы берутся из `src/config/tokens.css`. Сырые `#fff` или `16px`
в компонентах запрещены. Тёмная тема делается через `light-dark()` в определении токена,
а не отдельным блоком в компоненте: нужен другой цвет — заводите токен. Переключателя
темы на сайте нет: тема всегда приходит с устройства (`prefers-color-scheme`).
Классы — BEM внутри компонента (`.header__nav-link`). Брейкпоинты: 360 / 768 / 1024 / 1440,
mobile-first, тач-таргеты не меньше 44px.

**4. Контакты и реквизиты — только из `siteConfig`.**
`import { siteConfig } from '@/config/site'`. Телефон и email различаются между dev и prod,
хардкод в разметке рассылает заявки не туда.

Импорты — через единый алиас: `import Button from '@/components/atoms/button.astro'`.

## SEO: чего нельзя ломать

- **URL** — английские вложенные, всегда с завершающим слешем: `/catalog/<категория>/<товар>/`.
  Это `trailingSlash: 'always'` + `build.format: 'directory'` в `astro.config.ts`.
- **Переименовали или удалили страницу — добавьте старый адрес в `.documentation/redirects.md`.**
  Карта 301 применяется на сервере при деплое; без неё теряется поисковый индекс.
- **H1 ≠ title.** В контенте это разные поля: `title` (H1 для людей) и `seoTitle` (`<title>`,
  не длиннее 60 символов). Бренд к заголовку добавляет `buildTitle` из `lib/seo.ts` — и только
  если хвост помещается целиком.
- **Каждая страница** отдаёт уникальные title/description, canonical и Open Graph — всё через
  пропсы `BaseLayout`, руками в `<head>` ничего не дописываем.
- **JSON-LD** — только через генераторы из `lib/seo.ts`. Разметка организации подключена в
  шаблоне и попадает на все страницы.
- **Карта сайта** — `src/pages/sitemap.xml.ts`: адреса страниц и все фотографии с подписями
  одним файлом, без внешней интеграции.
- **Цены не публикуем** (решение владельца). CTA — «Рассчитать стоимость».

## Контент: как добавить товар, категорию или услугу

Каталог — markdown в `src/content/catalog/`. Имя файла = последний сегмент URL:

```
src/content/catalog/chimney-caps.md              → /catalog/chimney-caps/
src/content/catalog/post-cap.md                  → /catalog/chimney-caps/post-cap/
src/content/catalog/chimney-installation.md      → /services/chimney-installation/
src/content/catalog/<slug>/*.webp                # фото этого раздела рядом с текстом
src/content/_shared/*.webp                       # снимки, которые нужны нескольким разделам
```

Куда попадёт страница, решает поле `type`: `category` → `/catalog/<slug>/`,
`product` → `/catalog/<категория>/<slug>/` (категория берётся из поля `category`),
`service` → `/services/<slug>/`. Отдельных файлов роутинга создавать не нужно — страница
появится сама.

Заголовок файла (схема — `src/content.config.ts`, сборка падает при нарушении):

```yaml
---
type: product
title: Колпак на столб забора # H1 для людей
navTitle: Колпак на столб # короткое имя для меню, карточек, крошек
seoTitle: Колпаки на столбы забора в Минске # <title>, максимум 60 символов
description: Изготавливаем колпаки на столбы… # meta description, 80–165 символов
lead: Абзац под заголовком. # лид
category: chimney-caps # только для type: product
order: 30 # порядок в списках
featured: false # выводить на главной
cover: ./post-cap.webp
coverAlt: Колпак на кирпичном столбе забора
images:
  - src: ./post-cap-2.webp
    alt: Колпак на столб из оцинкованной стали
---
Текст страницы в markdown.
```

`alt` обязателен у каждого фото и должен быть осмысленным по-русски: тот же текст уходит
в подпись `ImageObject` и в карту изображений — по нему фото находят в поиске.

**Фотографии.** Держите исходники лёгкими и в WebP: Astro копирует в сборку оригиналы всех
импортированных фото, даже те, на которые нет ссылок (отключить нельзя — страницы
рендерятся после обработки ассетов). Лишний вес исходников переезжает в `dist` один в один.

Размеры и качество не задаются в компонентах — только пресетами из `lib/images.ts`
(`PHOTO_FULL`, `PHOTO_THUMB_WIDTHS`, `OG_IMAGE`). Одинаковые параметры в разных местах дают
один файл в сборке, свои числа в вызовах `getImage` плодят копии. Превью выводятся через
`atoms/picture.astro` (AVIF + WebP, srcset без апскейла).

## Окружение и форма заявки

Контакты компании заданы прямо в `config/site.ts` — телефон и email одинаковые в dev и prod.
Из окружения приходит только ключ формы: `.env.development` (dev-сервер) и `.env.production`
(сборка); схема — блок `env` в `astro.config.ts`, единственный читатель — тот же `config/site.ts`.

```
WEB3FORMS_KEY=""
```

Форма заказа отправляется в Web3Forms без своего бекенда. **Пустой `WEB3FORMS_KEY` = демо-режим:**
письмо не уходит, но пользователю показывается обычный экран успеха с пометкой «тестовый режим».
Ключ создаётся на web3forms.com на рабочий email.

Антиспам: скрытое поле-приманка плюс проверка времени заполнения — отправка быстрее трёх
секунд считается ботом и письмо не отправляет.

**Правовая обвязка формы.** Web3Forms — уполномоченное лицо: заявка уходит на серверы в США
(оператор сервиса — Web3Creative, Индия). Сам факт передачи сервису доставки писем описан
в разделе 4 `pages/privacy-policy.astro`; страна получателя и характер риска на сайте
не раскрываются — решение владельца от 19.08.2026, открытый пункт в разделе LEGAL `TODO.md`.
**Меняете приёмник формы — правьте политику**, иначе она начнёт врать (НЦЗПД считает это
нарушением само по себе). Владельцу нужно принять DPA сервиса на `web3forms.com/dpa` — это
и есть договор по ст. 7.

## Грабли, на которые уже наступали

- **Фоновый dev-сервер «протухает».** Каталог пустеет, страницы из коллекции отдают 404,
  в `.astro/dev.log` — «The collection "catalog" does not exist or is empty». Лечится
  перезапуском: `npm run stop && npm run dev`. Смотреть сайт «как в проде» надёжнее через
  `npm run build && npm run preview`.
- **Node ниже 22.12** — Astro 7 падает на старте с невнятной ошибкой.
- **`.documentation/deprecated/`** — только чтение, это зеркало старого сайта для справки.
- **Зависимости не добавляем без нужды**, jQuery и UI-библиотеки запрещены: весь интерактив
  (меню, лайтбокс, форма) — свои функции в `lib/`, суммарно несколько килобайт.

## Деплой

Хостинг и домен уже приобретены — **domain.by**, виртуальный хостинг: CloudLinux + ispmanager,
Apache 2.4 с `.htaccess` за nginx 1.28, PHP 8.4–5.2, Node.js 12.x–25.x, Python 3.8–3.13,
SSH и FTP, cron, бесплатный SSL, почтовые ящики на домене (SMTP/POP3/IMAP, до 400 писем/час).
Лимиты, о которые можно удариться: nginx — таймаут 60 с и тело запроса 30 Мб, PHP — 90 с и
512 Мб. Серверную часть (свой обработчик формы) хостинг позволяет — это проверено, решение
отложено сознательно, детали в разделе LEGAL `TODO.md`.

Важно при любом будущем переезде: по Указу № 60 ИП Беларуси
вправе вести деятельность через интернет только с ресурса, размещённого на территории РБ и
внесённого в Госреестр (заявление подаёт сам хостер), причём зона домена роли не играет —
важно физическое расположение сервера. Netlify, Vercel, Cloudflare Pages и GitHub Pages
как основная площадка не подходят, поэтому заголовки и редиректы настраиваются через
`.htaccess`/nginx, а не файлами конфигурации этих платформ.

Сборка — обычный статический `dist/`, выкладывается как есть.

**Всё поведение сервера собрано в `public/.htaccess`** — он копируется в корень сборки:
301-редиректы со всех 31 старого адреса, http → https, www → без www, добавление
завершающего слеша, кэш-заголовки, brotli/gzip, своя 404-я и заголовки безопасности.
Проверено на локальном Apache 2.4: каждый старый адрес отдаёт 301 ровно на тот адрес,
что записан в `.documentation/redirects.md`, одним переходом.

Два подводных камня:

- **Файл читают только Apache и LiteSpeed.** nginx его игнорирует, ничего об этом не сообщая:
  редиректы просто не работают, а узнаете вы об этом по упавшему трафику. Первым делом после
  деплоя — `curl -I https://metallomaster.by | grep -i server`.
- **HSTS намеренно выставлен на `max-age=300`.** Пока так, ошибку с сертификатом можно
  откатить за пять минут. Через неделю спокойной работы значение меняется на два года —
  об этом есть пункт в `TODO.md`. Сразу ставить два года нельзя: браузеры запомнят
  требование https на весь срок, и откатиться будет невозможно.

CSP лежит в файле закомментированной: включать её нужно сначала в режиме отчётов
(`Content-Security-Policy-Report-Only`) и переводить в боевой режим, когда консоль чиста.
Порядок описан там же в комментарии.

Набор проверок после деплоя — в шапке `public/.htaccess`.

Счётчиков аналитики на сайте нет осознанно — отсюда и отсутствие cookie-баннера: сайт
не пишет в localStorage и cookie ничего. Если аналитику решат подключить, баннер
добавляется тем же пакетом.
